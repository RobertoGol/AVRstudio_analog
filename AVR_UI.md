# Справочник интерфейса AVR Studio 4 и архитектуры ATmega8/ATmega8A

С учетом всех предоставленных файлов, структуры меню, карты периферии и синтаксиса директив, ниже представлена **абсолютная и исчерпывающая техническая база** для работы с микроконтроллером **ATmega8/ATmega8A** в среде **AVR Studio 4**.

---

## I. ПОЛНЫЙ НАБОР ДИРЕКТИВ АССЕМБЛЕРА AVR STUDIO 4
Директивы управляют компилятором, размечают память данных (`SRAM`), программ (`Flash`) и `EEPROM`. Они начинаются строго с точки (`.`):

*   **.include** `"m8Adef.inc"` — Подключение внешнего файла описания архитектуры МК.
*   **.cseg** — Переключение в сегмент **памяти программ (Flash)** для исполняемого кода.
*   **.dseg** — Переключение в сегмент **данных (SRAM)** для выделения ОЗУ под переменные.
*   **.eseg** — Переключение в сегмент **энергонезависимой памяти (EEPROM)**.
*   **.org** `адрес` — Установка счетчика адреса компилятора на указанную ячейку.
*   **.def** `имя = регистр` — Назначение символического имени регистру общего назначения (`R0-R31`).
*   **.equ** `имя = значение` — Объявление константы, которую нельзя переопределить в коде.
*   **.set** `имя = значение` — Объявление константы, значение которой можно менять далее по коду.
*   **.db** / **.dw** — Внедрение массива 8-битных байт / 16-битных слов в текущую позицию (только в `.cseg` и `.eseg`).
*   **.byte** `число` — Резервирование определенного количества байт памяти в ОЗУ (только в `.dseg`).
*   **.macro** `имя` / **.endmacro** — Начало и конец объявления макрокоманды препроцессора.

---

## II. СИСТЕМНЫЕ МАТЕМАТИЧЕСКИЕ ФУНКЦИИ И ОПЕРАТОРЫ
Применяются для автоматического расчета параметров таймеров, битовых масок и адресов:
*   **low(**`выражение`**)** / **high(**`выражение`**)** — Возвращает младший (биты 0–7) / старший (биты 8–15) байт выражения (используется для инициализации указателя стека `SPH`:`SPL`).
*   Математические операторы: `+`, `-`, `*`, `/`, `<<` (побитовый сдвиг влево), `>>` (сдвиг вправо), `~` (инверсия), `&` (И), `|` (ИЛИ), `^` (XOR).

---

## III. ПОЛНАЯ ТАБЛИЦА ВЕКТОРОВ ПРЕРЫВАНИЙ ATmega8 / ATmega8A
Занимает адреса `0x000`–`0x012` в памяти программ. Архитектурно требует использования исключительно относительных переходов **`RJMP`**:

```assembly
.cseg
.org 0x0000
    rjmp Reset      ; 1. Reset — Сброс МК, старт программы (высший приоритет)
    rjmp INT0_ISR   ; 2. INT0 — Внешнее прерывание на входе PD2 (пин 4)
    rjmp INT1_ISR   ; 3. INT1 — Внешнее прерывание на входе PD3 (пин 5)
    rjmp OC2_ISR    ; 4. TIMER2 COMP — Совпадение таймера/счетчика 2
    rjmp OVF2_ISR   ; 5. TIMER2 OVF — Переполнение таймера/счетчика 2
    rjmp ICP1_ISR   ; 6. TIMER1 CAPT — Захват фронта таймером/счетчиком 1
    rjmp OC1A_ISR   ; 7. TIMER1 COMPA — Совпадение "A" таймера/счетчика 1
    rjmp OC1B_ISR   ; 8. TIMER1 COMPB — Совпадение "B" таймера/счетчика 1
    rjmp OVF1_ISR   ; 9. TIMER1 OVF — Переполнение таймера/счетчика 1
    rjmp OVF0_ISR   ; 10. TIMER0 OVF — Переполнение таймера/счетчика 0
    rjmp SPI_ISR    ; 11. SPI, STC — Окончание последовательной передачи SPI
    rjmp RXC_ISR    ; 12. USART, RXC — USART прием завершен (пришел байт)
    rjmp UDRE_ISR   ; 13. USART, UDRE — Регистр данных USART пуст
    rjmp TXC_ISR    ; 14. USART, TXC — USART передача завершена
    rjmp ADC_ISR    ; 15. ADC — Преобразование АЦП завершено
    rjmp EE_ISR     ; 16. EE_RDY — Память EEPROM готова к записи/чтению
    rjmp ANA_COMP   ; 17. ANA_COMP — Срабатывание аналогового компаратора
    rjmp TWI_ISR    ; 18. TWI — Прерывание двухпроводного интерфейса I2C
    rjmp SPM_ISR    ; 19. SPM_RDY — Память программ готова (освободился буфер SPM)

.org 0x0030         ; Обход таблицы прерываний для начала основного кода
Reset:
```

## IV. КАРТА РЕГИСТРОВ И СИСТЕМНЫХ ИМЕН ПЕРИФЕРИИ (ДЛЯ ПАНЕЛИ I/O VIEW)
Эти имена жестко закреплены в файле описания и служат аргументами для команд **`IN`**, **`OUT`**, **`SBI`**, **`CBI`**:

*   **Границы Памяти:** `FLASHEND` (`0x0FFF`), `SRAM_START` (`0x0060`), `RAMEND` (`0x045F`), `E2END` (`0x01FF`).
*   **Вычислительное Ядро (CPU):** `SREG` (регистр флагов), `SPH` / `SPL` (регистры указателя стека), `MCUCR`, `MCUCSR` (управление сбросом и сном), `OSCCAL` (калибровка внутреннего генератора), `SFIOR`, `SPMCR` (самопрограммирование Flash).
*   **Порты Ввода-Вывода:**
    *   Порт B: `PORTB`, `DDRB`, `PINB`.
    *   Порт C: `PORTC`, `DDRC`, `PINC`.
    *   Порт D: `PORTD`, `DDRD`, `PIND`.
*   **Таймеры и Счетчики:**
    *   Таймер 0 (8 бит): `TCCR0` (регистр управления), `TCNT0` (счетный регистр).
    *   Таймер 1 (16 бит): `TCCR1A`, `TCCR1B` (управление), `TCNT1H` / `TCNT1L` (счетный регистр), `OCR1AH` / `OCR1AL` (регистр совпадения A), `OCR1BH` / `OCR1BL` (регистр совпадения B), `ICR1H` / `ICR1L` (регистр захвата).
    *   Таймер 2 (8-битный асинхронный): `TCCR2` (управление), `TCNT2` (счетчик), `OCR2` (регистр совпадения), `ASSR` (асинхронный режим).
*   **Интерфейсы Связи:**
    *   USART (Последовательный порт): `UDR` (регистр данных), `UCSRA`, `UCSRB`, `UCSRC` (регистры управления/статуса), `UBRRH`, `UBRRL` (скорость передачи).
    *   SPI: `SPCR` (управление), `SPSR` (статус), `SPDR` (регистр данных).
    *   TWI (Hardware I2C): `TWBR` (регистр битовой скорости), `TWCR` (управление), `TWSR` (статус), `TWDR` (регистр данных), `TWAR` (адресный регистр).
*   **Аналоговые модули и Системный контроль:**
    *   Аналого-цифровой преобразователь (АЦП): `ADMUX` (выбор канала/опоры), `ADCSRA` (статус и запуск преобразования), `ADCH` / `ADCL` (результат в байтах).
    *   Аналоговый компаратор: `ACSR` (управление и статус).
    *   Сторожевой таймер: `WDTCR` (регистр контроля Watchdog).
    *   EEPROM: `EEARH` / `EEARL` (адрес), `EEDR` (данные), `EECR` (управление чтением/записью).
    *   Внешние прерывания: `GICR` (регистр разрешения `INT0`/`INT1`), `GIFR` (регистр флагов), `TIMSK` (маска прерываний таймеров), `TIFR` (флаги таймеров).

## V. ИСЧЕРПЫВАЮЩИЙ СПИСОК ВСЕХ АППАРАТНЫХ КОМАНД ATmega8/ATmega8A
Полная RISC-архитектура ядра `avr4` включает ровно **130 команд**. В таблице ниже приведен их точный ассемблерный синтаксис.

*Обозначения: `Rd`, `Rr` — регистры общего назначения (`R0-R31`), `K`, `k` — константы/адреса меток, `A` — адрес регистра ввода-вывода (`0-63`), `b` — номер бита (`0-7`), `q` — смещение адреса (`0-63`).*

### 1. Арифметические и логические операции (АЛУ)

| Команда | Синтаксис | Ограничения на аргументы | Описание операции |
| :--- | :--- | :--- | :--- |
| **`ADD`** | `ADD Rd, Rr` | `d, r: 0..31` | Сложение регистров: Rd = Rd + Rr |
| **`ADC`** | `ADC Rd, Rr` | `d, r: 0..31` | Сложение с переносом: Rd = Rd + Rr + C |
| **`ADIW`** | `ADIW Rd, K` | `d: 24, 26, 28, 30; K: 0..63` | Прибавить константу к паре (`R25:R24`, `X`, `Y`, `Z`) |
| **`SUB`** | `SUB Rd, Rr` | `d, r: 0..31` | Вычитание регистров: Rd = Rd - Rr |
| **`SUBI`** | `SUBI Rd, K` | `d: 16..31; K: 0..255` | Вычесть константу из регистра |
| **`SBC`** | `SBC Rd, Rr` | `d, r: 0..31` | Вычитание с заёмом: Rd = Rd - Rr - C |
| **`SBCI`** | `SBCI Rd, K` | `d: 16..31; K: 0..255` | Вычесть константу с заёмом |
| **`SBIW`** | `SBIW Rd, K` | `d: 24, 26, 28, 30; K: 0..63` | Вычесть константу из пары регистров |
| **`AND`** | `AND Rd, Rr` | `d, r: 0..31` | Побитовое И: Rd = Rd & Rr |
| **`ANDI`** | `ANDI Rd, K` | `d: 16..31; K: 0..255` | Побитовое И регистра с константой (маска) |
| **`OR`** | `OR Rd, Rr` | `d, r: 0..31` | Побитовое ИЛИ: Rd = Rd \| Rr |
| **`ORI`** | `ORI Rd, K` | `d: 16..31; K: 0..255` | Побитовое ИЛИ регистра с константой |
| **`EOR`** | `EOR Rd, Rr` | `d, r: 0..31` | Исключающее ИЛИ: Rd = Rd ^ Rr |
| **`COM`** | `COM Rd` | `d: 0..31` | Побитовое инвертирование (1 в 0, 0 в 1) |
| **`NEG`** | `NEG Rd` | `d: 0..31` | Дополнение до двух (умножение регистра на -1) |
| **`INC`** | `INC Rd` | `d: 0..31` | Инкремент: Rd = Rd + 1 (флаг переноса C не меняется) |
| **`DEC`** | `DEC Rd` | `d: 0..31` | Декремент: Rd = Rd - 1 |
| **`TST`** | `TST Rd` | `d: 0..31` | Проверка регистра на ноль или отрицательный знак |
| **`CLR`** | `CLR Rd` | `d: 0..31` | Очистить регистр (Rd = 0) |
| **`SER`** | `SER Rd` | `d: 16..31` | Записать в регистр константу 0xFF |
| **`MUL`** | `MUL Rd, Rr` | `d, r: 0..31` | Умножение без знака (Результат в паре R1:R0) |
| **`MULS`** | `MULS Rd, Rr` | `d, r: 16..31` | Умножение со знаком (Результат в R1:R0) |
| **`MULSU`**| `MULSU Rd, Rr`| `d, r: 16..23` | Умножение знакового числа на беззнаковое |
| **`FMUL`** | `FMUL Rd, Rr` | `d, r: 16..23` | Дробное умножение без знака |
| **`FMULS`**| `FMULS Rd, Rr`| `d, r: 16..23` | Дробное умножение со знаком |
| **`FMULSU`**| `FMULSU Rd, Rr`| `d, r: 16..23` | Дробное умножение знакового на беззнаковое |

### 2. Перемещения данных и операции с памятью

| Команда | Синтаксис | Ограничения на аргументы | Описание операции |
| :--- | :--- | :--- | :--- |
| **`MOV`** | `MOV Rd, Rr` | `d, r: 0..31` | Скопировать значение регистра: Rd = Rr |
| **`MOVW`** | `MOVW Rd, Rr` | `d, r: четные пары` | Копировать регистровую пару в другую |
| **`LDI`** | `LDI Rd, K` | `d: 16..31; K: 0..255` | Загрузить число/константу напрямую в регистр |
| **`LDS`** | `LDS Rd, k` | `d: 0..31; k: 0..65535` | Прямое чтение байта из ячейки ОЗУ k в Rd |
| **`STS`** | `STS k, Rr` | `r: 0..31; k: 0..65535` | Прямая запись байта из Rr в ячейку ОЗУ k |
| **`IN`** | `IN Rd, A` | `d: 0..31; A: 0..63` | Прочитать значение из регистра периферии A в Rd |
| **`OUT`** | `OUT A, Rr` | `A: 0..63; r: 0..31` | Записать значение из Rr в регистр периферии A |
| **`PUSH`** | `PUSH Rr` | `r: 0..31` | Положить значение регистра Rr в текущую ячейку Стека |
| **`POP`** | `POP Rd` | `d: 0..31` | Извлечь значение из Стека в регистр Rd |

*Косвенная адресация через пары X, Y, Z:*
*   `LD Rd, X` / `LD Rd, Y` / `LD Rd, Z` — Косвенное чтение из SRAM по адресу в указателе.
*   `LD Rd, X+` / `LD Rd, Y+` / `LD Rd, Z+` — Косвенное чтение с автоинкрементом адреса на 1.
*   `LD Rd, -X / LD Rd, -Y / LD Rd, -Z` — Автодекремент адреса на 1 перед косвенным чтением.
*   `LDD Rd, Y+q / LDD Rd, Z+q` — Косвенное чтение из SRAM со смещением q (0..63).
*   `ST X, Rr / ST Y, Rr / ST Z, Rr` — Косвенная запись из Rr по адресу в указателе.
*   `ST X+, Rr / ST Y+, Rr / ST Z+, Rr` — Косвенная запись с автоинкрементом адреса на 1.
*   `ST -X, Rr / ST -Y, Rr / ST -Z, Rr` — Автодекремент адреса на 1 перед косвенной записью.
*   `STD Y+q, Rr / STD Z+q, Rr` — Косвенная запись из Rr со смещением q (0..63).
Операции с энергонезависимой памятью программ:
*   `LPM` — Прочитать байт из Flash по адресу указателя Z и сохранить его строго в R0.
*   `LPM Rd, Z` — Прочитать байт из Flash по адресу Z и сохранить его в выбранный регистр Rd.
*   `LPM Rd, Z+` — Чтение из Flash во внутренний РОН с последующим автоинкрементом указателя Z.
*   `SPM` — Запись страницы памяти программ (разрешена только в специальной секции Bootloader).

### 3. Битовые инструкции и работа с флагами SREG

| Команда | Синтаксис | Диапазон аргументов | Описание операции |
| :--- | :--- | :--- | :--- |
| **`SBI`** | `SBI A, b` | `A: 0..31; b: 0..7` | Установить в 1 бит b порта/регистра ввода-вывода |
| **`CBI`** | `CBI A, b` | `A: 0..31; b: 0..7` | Сбросить в 0 бит b порта/регистра ввода-вывода |
| **`LSL`** | `LSL Rd` | `d: 0..31` | Логический сдвиг влево (Младший бит равен 0, старший уходит в C) |
| **`LSR`** | `LSR Rd` | `d: 0..31` | Логический сдвиг вправо (Старший бит равен 0, младший уходит в C) |
| **`ROL`** | `ROL Rd` | `d: 0..31` | Циклический сдвиг влево (Старший бит идет в C, старый C — в младший бит) |
| **`ROR`** | `ROR Rd` | `d: 0..31` | Циклический сдвиг вправо (Младший бит идет в C, старый C — в старший бит) |
| **`ASR`** | `ASR Rd` | `d: 0..31` | Арифметический сдвиг вправо (Сохраняет знаковый бит 7 без изменений) |
| **`SWAP`**| `SWAP Rd` | `d: 0..31` | Поменять местами полубайты (биты 0-3 меняются местами с битами 4-7) |
| **`BSET`**| `BSET s` | `s: 0..7` | Установить в 1 флаг номер s в статусном регистре SREG |
| **`BCLR`**| `BCLR s` | `s: 0..7` | Сбросить в 0 флаг номер s в статусном регистре SREG |
| **`BST`** | `BST Rd, b`| `d: 0..31; b: 0..7` | Скопировать бит b регистра во временный флаг T регистра SREG |
| **`BLD`** | `BLD Rd, b`| `d: 0..31; b: 0..7` | Скопировать бит из временного флага T обратно в бит b регистра |

*Быстрые непараметрические инструкции управления флагами SREG:*
*   `SEC` / `CLC` — Установить / сбросить флаг переноса C.
*   `SEN` / `CLN` — Установить / сбросить флаг отрицательного результата N.
*   `SEZ` / `CLZ` — Установить / сбросить флаг нулевого значения Z.
*   `SEI` / `CLI` — Глобально разрешить / запретить прерывания (бит общего контроля прерываний I).
*   `SES` / `CLS` — Установить / сбросить флаг знаковой логики S.
*   `SEV` / `CLV` — Установить / сбросить флаг арифметического переполнения V.
*   `SET` / `CLT` — Установить / сбросить пользовательский бит T.
*   `SEH` / `CLH` — Установить / сбросить флаг полупереноса H.

### 4. Команды ветвления, условий и управления ходом программы

| Команда | Синтаксис | Диапазон аргументов | Описание операции |
| :--- | :--- | :--- | :--- |
| **`RJMP`** | `RJMP k` | `k: -2048..2047` | Относительный прыжок по коду на метку k |
| **`IJMP`** | `IJMP` | *нет аргументов* | Косвенный переход по адресу, загруженному в пару Z |
| **`RCALL`**| `RCALL k` | `k: -2048..2047` | Относительный вызов функции/подпрограммы с записью ПК в Стек |
| **`ICALL`**| `ICALL` | *нет аргументов* | Косвенный вызов подпрограммы по адресу в паре регистров Z |
| **`RET`** | `RET` | *нет аргументов* | Извлечь адрес возврата из Стека и вернуться из подпрограммы |
| **`RETI`** | `RETI` | *нет аргументов* | Возврат из прерывания с автоматической установкой бита I в 1 |
| **`CPSE`** | `CPSE Rd, Rr` | `d, r: 0..31` | Сравнить регистры. Пропустить следующую команду, если они равны |
| **`CP`** | `CP Rd, Rr` | `d, r: 0..31` | Сравнить регистры без изменения данных (меняет флаги SREG) |
| **`CPC`** | `CPC Rd, Rr` | `d, r: 0..31` | Сравнить регистры с учетом флага переноса/заёма C |
| **`CPI`** | `CPI Rd, K` | `d: 16..31; K: 0..255` | Сравнить значение регистра с константой/числом |
| **`SBRC`** | `SBRC Rr, b` | `r: 0..31; b: 0..7` | Пропустить следующую команду, если бит b в Rr сброшен в 0 |
| **`SBRS`** | `SBRS Rr, b` | `r: 0..31; b: 0..7` | Пропустить следующую команду, если бит b в Rr равен 1 |
| **`SBIC`** | `SBIC A, b` | `A: 0..31; b: 0..7` | Пропустить команду, если бит b регистра ввода-вывода A равен 0 |
| **`SBIS`** | `SBIS A, b` | `A: 0..31; b: 0..7` | Пропустить команду, если бит b регистра ввода-вывода A равен 1 |
| **`BRBS`** | `BRBS s, k` | `s: 0..7; k: -64..63` | Перейти к метке k, если флаг состояния s равен 1 |
| **`BRBC`** | `BRBC s, k` | `s: 0..7; k: -64..63` | Перейти к метке k, если флаг состояния s равен 0 |

*Автоматические псевдонимы условных переходов (Синтаксис: ИМЯ метка):*
*   `BREQ` / `BRNE` — Переход, если равно / не равно (по состоянию флага Z).
*   `BRCS` / `BRCC` — Переход, если перенос установлен / сброшен (по состоянию флага C).
*   `BRSH` / `BRLO` — Переход, если unsigned значение больше-равно / меньше.
*   `BRMI` / `BRPL` — Переход, если результат вычисления минус / плюс (по флагу N).
*   `BRGE` / `BRLT` — Переход, если больше-равно / меньше (для чисел со знаком).
*   `BRHS` / `BRHC` — Переход, если полуперенос установлен / сброшен (по флагу H).
*   `BRTS` / `BRTC` — Переход, если флаг пользователя T установлен / сброшен.
*   `BRVS` / `BRVC` — Переход, если арифметическое переполнение произошло / отсутствует.
*   `BRIE` / `BRID` — Переход, если прерывания глобально разрешены / запрещены.

### 5. Инструкции системного контроля ядра (Не принимают параметров)
*   **`NOP`** — Пустая операция (Процессор ровно 1 такт ничего не делает, используется для задержек шины).
*   **`SLEEP`** — Остановка такторования и перевод ядра в энергосберегающий режим (режим выбирается в MCUCR).
*   **`WDR`** — Инструкция сброса сторожевого таймера (Watchdog Reset) для исключения перезапуска МК.
*   **`BREAK`** — Остановка ядра в точке вызова для передачи управления аппаратному отладчику.


## VI. СТРУКТУРА ОКН ДИГНОСТИКИ И ИНТЕРФЕЙСА IDE (WORKSPACE)

Для точной симуляции визуального отображения среды разработки, дерево окон и параметры конфигурации разделены на четыре функциональных блока.

### 1. Вычислительное ядро процессора (Панель Processor)
Отображает текущее внутреннее состояние вычислительного блока во время пошаговой отладки:
*   **Базовые указатели и счетчики:** 
    *   `Program Counter` — Счетчик команд (указывает на текущую исполняемую ячейку памяти программ).
    *   `Stack Pointer` — Указатель стека (`SPH:SPL`).
    *   `Cycle Counter` — Счетчик тактов (количество машинных циклов, выполненных с начала старта).
    *   `Frequency` — Тактовая частота симуляции.
    *   `Stop Watch` — Секундомер реального времени выполнения.
*   **Индексные регистровые пары:** `X pointer` (`R27:R26`), `Y pointer` (`R29:R28`), `Z pointer` (`R31:R30`).
*   **Статусный регистр флагов (SREG):** Побитовое отображение флагов `I`, `T`, `H`, `S`, `V`, `N`, `Z`, `C`.
*   **Регистры общего назначения (РОН):** Список значений всей линейки тридцати двух регистров процессора от `R00` до `R31`.

### 2. Системный Workspace и Ошибки (Панели дерева проекта и сообщений)
*   **Структура логического дерева проекта:**
    *   `Source Files` — Папка исходных кодов (содержит главный рабочий файл `.asm` или `.c`).
    *   `Header Files` — Заголовочные файлы описания.
    *   `External Dependencies` — Внешние зависимости и подключаемые библиотеки.
    *   `Other Files` — Вспомогательные файлы конфигурации.
*   **Логи отладочной панели Message:**
    *   Выводит системные предупреждения об успешной инициализации плагинов (например, `Loaded plugin STK500`, `Loaded plugin AVR GCC`).
    *   Выводит лог загрузки XML-описания архитектуры целевого чипа (например, `Loaded partfile... ATmega8.xml`).
    *   Критические ошибки компиляции и препроцессора (например, `Project is readonly and cannot be saved` при запрете записи в защищенные системные директории вроде `system32` или `Failed to open file`).
*   **Дополнительные панели отладки:**
    *   `Build` — Окно хода сборки проекта, объема задействованной памяти Flash/SRAM и подсчета количества Warns/Errors.
    *   `Find in Files` — Результаты глобального поиска по коду проекта.
    *   `Breakpoints and Tracepoints` — Менеджер управления установленными точками останова программы и логирования данных.

### 3. Инструментальные панели и кнопки быстрого доступа

## VIII. ПОБИТОВАЯ СТРУКТУРА УПРАВЛЯЮЩИХ РЕГИСТРОВ (ДЛЯ ЭМУЛЯЦИИ ПАНЕЛИ I/O)

Для того чтобы локальный AI мог эмулировать пошаговое изменение логических уровней (битов) при симуляции кода, ниже приведена детальная структура основных управляющих регистров ядра микроконтроллера согласно панели I/O View.

### 1. Регистр статуса процессора — SREG (Address: 0x3F / 0x5F)
Хранит текущее состояние арифметико-логического устройства после выполнения команд:
*   `Bit 7 — I (Global Interrupt Enable):` Глобальное разрешение прерываний (управляется командами `SEI`/`CLI`).
*   `Bit 6 — T (Bit Copy Storage):` Бит копирования (используется командами `BST`/`BLD`).
*   `Bit 5 — H (Half Carry Flag):` Флаг полупереноса (перенос из 3-го бита в 4-й, важен для BCD-арифметики).
*   `Bit 4 — S (Sign Bit):` Флаг знака (всегда равен \(N \oplus V\), определяет истинный знак результата).
*   `Bit 3 — V (Two's Complement Overflow Flag):` Флаг арифметического переполнения для чисел со знаком.
*   `Bit 2 — N (Negative Flag):` Флаг отрицательного результата (дублирует старший 7-й бит результата).
*   `Bit 1 — Z (Zero Flag):` Флаг нулевого результата (устанавливается в 1, если результат операции равен 0).
*   `Bit 0 — C (Carry Flag):` Флаг переноса или заёма из старшего бита.

### 2. Регистр управления микроконтроллером — MCUCR (Address: 0x35 / 0x55)
*   `Bit 7..6 — Резерв:` Не используются в ATmega8.
*   `Bit 5 — SE (Sleep Enable):` Разрешение перехода в режим сна по команде `SLEEP`.
*   `Bit 4..2 — SM2:SM0 (Sleep Mode Select Bits):` Выбор режима энергосбережения (Idle, Power-down, Power-save, ADC Noise Reduction, Standby).
*   `Bit 1 — ISC11 / Bit 0 — ISC10 (Interrupt Sense Control 1):` Настройка условий срабатывания внешнего прерывания `INT1` (по низкому уровню, по любому фронту, по спадающему или по нарастающему фронту).
*   `Bit 3 — ISC01 / Bit 2 — ISC00 (Interrupt Sense Control 0):` Настройка условий срабатывания внешнего прерывания `INT0`.

### 3. Регистр управления и статуса — MCUCSR (Address: 0x34 / 0x54)
Определяет источник последнего сброса (Reset) микроконтроллера:
*   `Bit 3 — WDRF (Watchdog Reset Flag):` Сброс произошел по таймауту сторожевого таймера.
*   `Bit 2 — BORF (Brown-out Reset Flag):` Сброс из-за падения напряжения питания ниже критического порога.
*   `Bit 1 — EXTRF (External Reset Flag):` Сброс вызван подачей низкого уровня на физический вывод `RESET` (пин 1).
*   `Bit 0 — PORF (Power-on Reset Flag):` Сброс при первоначальном включении питания.

### 4. Регистр управления памятью программ — SPMCR (Address: 0x37 / 0x57)
Используется командой `SPM` для самопрошивки контроллера:
*   `Bit 7 — SPMIE (SPM Interrupt Enable):` Разрешение прерывания по готовности памяти программ.
*   `Bit 6 — RWWSB (Read-While-Write Section Busy):` Флаг занятости RWW-секции памяти.
*   `Bit 5 — Резерв.`
*   `Bit 4 — RWWSRE (Read-While-Write Section Read Enable):` Разрешение чтения секции RWW.
*   `Bit 3 — BLBSET (Boot Lock Bit Set):` Установка битов защиты загрузчика.
*   `Bit 2 — PGWRT (Page Write):` Запуск записи страницы Flash-памяти из временного буфера.
*   `Bit 1 — PGERS (Page Erase):` Запуск стирания выбранной страницы памяти программ.
*   `Bit 0 — SPMEN (Store Program Memory Enable):` Разрешение исполнения команды `SPM` в течение следующих 4 тактов.

### 5. Специальный функциональный регистр ввода-вывода — SFIOR (Address: 0x30 / 0x50)
*   `Bit 4 — ADHSM (ADC High Speed Mode):` Включение высокоскоростного режима аналого-цифрового преобразователя.
*   `Bit 2 — PUD (Pull-up Disable):` Глобальное отключение подтягивающих (Pull-up) резисторов на всех портах I/O.
*   `Bit 0 — PSR10 (Prescaler Reset Timer/Counter1 and Timer/Counter0):` Сброс общих предделителей для таймеров 0 и 1 при записи логической 1.

## X. АРХИТЕКТУРА И ГЕОМЕТРИЯ ЭКРАНА (GUI SCREEN MAP)

Этот раздел описывает точное взаимное расположение окон, вкладок и панелей на экране для локальной эмуляции интерфейса AVR Studio 4.

### 1. Главное окно программы (Main Application Window)
Верхнеуровневый контейнер интерфейса имеет жесткую вертикальную структуру:
1.  **Самая верхняя строка (Заголовок):** Отображает имя программы, имя открытого проекта и путь к текущему файлу (например, `AVR Studio - [C:\Project\Lab3.asm]`).
2.  **Вторая строка:** Главное выпадающее меню (`MainMenu`: File, Project, Build, View, Tools, Debug, Help).
3.  **Третья и четвертая строки:** Зона графических панелей инструментов (`Toolbars`). Панели можно откреплять и перемещать, но по умолчанию они расположены горизонтально в ряд:
    *   Слева: `Standard Toolbar` и `Edit` (иконки файлов и буфера).
    *   По центру: `Debug` и `TraceBar` (управление шагами отладки и выпадающий список выбора режима трассировки).
    *   Справа: `AVR Tools` и панели вызова диагностических окон.

### 2. Левая вертикальная рабочая зона (Панель Workspace)
Занимает левую четверть экрана. Представляет собой двухрежимное окно с вкладками в нижней части:
*   **Вкладка «Project» (Дерево проекта):**
    *   Корневой элемент: Жирным шрифтом выделено имя активного проекта (например, **First_Example**).
    *   Вложенные логические папки: `Source Files`, `Header Files`, `External Dependencies`, `Other Files`.
    *   *Технический маркер:* Если файл утерян на диске, иконка файла внутри `Source Files` перечеркивается красным крестиком.
*   **Вкладка «I/O» (Панель I/O View):**
    *   Представляет собой иерархическое дерево (`Tree View`) всех аппаратных модулей.
    *   При клике на модуль (например, `PORTB`) в нижней половине этого же окна разворачивается список его физических регистров (`PORTB`, `DDRB`, `PINB`), их шестнадцатеричные адреса и 8 интерактивных квадратиков-битов (белый цвет — 0, закрашенный/синий — 1).

### 3. Центральная рабочая зона (Main Code Space & Debug)
Занимает основную (центральную и правую) часть экрана. Работает в многодокументном интерфейсе (`MDI Tabs`):
*   **Окно исходного текста программы (Code Editor):**
    *   Основное текстовое поле с белым фоном. Номера строк отображаются на сером поле слева.
    *   *Цветовая схема синтаксиса:* Служебные команды процессора и директивы (`LDI`, `OUT`, `.cseg`) — **синие**; комментарии (`;` или `//`) — **зеленые**; пользовательские метки и имена — **черные**.
    *   *Маркеры отладки:* На левом сером поле отображаются **круглые бордовые точки** (Breakpoints). Во время отладки желтая стрелка (или цветной текстовый маркер строки) жестко указывает на инструкцию, которая будет выполнена в следующем цикле.
*   **Окно «Processor» (Диагностическая панель ядра):**
    *   Обычно открывается поверх рабочей зоны справа или как плавающее окно.
    *   Содержит строго структурированную таблицу из двух колонок: `Name` (Имя регистра или счетчика) и `Value` (Его текущее значение в шестнадцатеричном или десятичном формате). Все 32 регистра РОН сгруппированы под раскрывающимся заголовком `Registers`.

### 4. Нижняя горизонтальная рабочая зона (Панель Вывода)
Занимает всю нижнюю часть экрана по горизонтали. Содержит ключевые вкладки логов:
*   **Вкладка «Message» (Системный лог):**
    *   Текстовое поле, куда построчно выводятся системные сообщения и критические ошибки препроцессора (например, выделенные красной точкой строки: `• Project is readonly and cannot be saved`).
*   **Вкладка «Build» (Вывод сборщика):**
    *   Показывает ход трансляции кода ассемблером. При возникновении ошибки двойной клик по строке ошибки в этой вкладке автоматически перемещает курсор в окне кода на строку со сбоем алгоритма.
*   **Вкладка «Find in Files»:** Выводит список строк и путей к файлам, найденных через инструмент глобального поиска.
*   **Вкладка «Breakpoints and Tracepoints»:** Таблица со столбцами `Description` (описание точки останова, адрес памяти) и `Hit Count` (счетчик проходов отладчика через эту точку).

### 5. Самая нижняя строка (Status Bar)
Тонкая полоса в самом низу экрана, разделенная на секции:
*   Слева: Текущий статус (например, `Ready` или `Tracing Disabled`).
*   По центру: Имя выбранного контроллера и плагина симуляции (например, `ATmega8A`, `AVR Simulator 2`).
*   Справа: Координаты курсора в текстовом редакторе (`Ln 15, Col 5`) и состояние клавиш (`CAP`, `NUM`, `SCRL`).

## XI. АЛГОРИТМ ДИАЛОГА ПРИВЕТСТВИЯ И СОЗДАНИЯ ПРОЕКТА (WELCOME WIZARD)

При старте интерфейса локальный AI должен воспроизводить строго линейный процесс инициализации нового проекта через всплывающее окно **«Welcome to AVR Studio 4»**:

1.  **Окно 1: Приветствие (Welcome Dialog):**
    *   Кнопка `New Project` — Запуск мастера создания.
    *   Кнопка `Open` — Вызов стандартного системного проводника Windows (`Open Project File or Object File`) для выбора файлов с расширениями `*.aps`, `*.hex`, `*.obj`, `*.cof`, `*.dbg`.
2.  **Окно 2: Настройка проекта (Create New Project):**
    *   Поле выбора типа проекта (`Project type`): Два переключателя — `Atmel AVR Assembler` или `AVR GCC`.
    *   Поле ввода имени проекта (`Project name`).
    *   Флажки автоматизации: `[x] Create initial file` (Создать начальный файл `.asm` или `.c`) и `[x] Create folder` (Создать отдельную папку проекта).
    *   Поле пути (`Location`): По умолчанию среда пытается указать путь `C:\Windows\system32`. *Технический нюанс:* Для успешной сборки пользователь обязан изменить этот путь на личную рабочую папку в «Документах», иначе компилятор выдаст ошибку доступа к памяти.
    *   Управляющие кнопки снизу: `<< Back`, `Next >>`, `Finish` (неактивна до ввода имени), `Cancel`, `Help`.
3.  **Окно 3: Выбор платформы отладки (Select debug platform and device):**
    *   Левый список (`Debug platform`): Выбор отладчика (например, `AVR Simulator` или `JTAGICE mkII`).
    *   Правый список (`Device`): Выбор конкретной модели чипа. Доступны только те микроконтроллеры, которые аппаратно поддерживаются выбранной левой платформой (согласно *Таблице совместимости из раздела IX*). Для связки с ассемблером выбирается **ATmega8** или **ATmega8A**.
    *   Флажок внизу: `[ ] Open platform options next time debug mode is entered` (Открывать настройки платформы при каждом входе в режим отладки).
    *   Завершение: Клик по кнопке `Finish` закрывает мастер и генерирует рабочее пространство Workspace.

## XII. ТОЧНЫЕ ПИКСЕЛЬНЫЕ РАЗМЕРЫ, ОТСТУПЫ И ШРИФТЫ (UI GEOMETRY & SPECS)

Этот раздел содержит жесткие технические параметры элементов интерфейса (размеры в пикселях, шрифты и HEX-цвета) для точной верстки или обучения генеративной AI-модели.

*   **Элементы интерфейса (Меню, списки, дерево I/O, Processor):** `MS Sans Serif` или `Tahomа`, размер **8pt** (11px). Начертание: Regular (активные элементы в дереве проекта — Bold).
*   **Окно редактора кода и Вывод логов (Message, Build):** Моноширинный шрифт `Courier New`, размер **10pt** (13px), межстрочный интервал (line-height) — **120%** (16px).

### 2. Главное окно и верхние панели (Вертикальная сетка)
*   **Высота главного заголовка окна (Title Bar):** **30px**.
*   **Высота Главного меню (MainMenu):** **22px**. Отступы текста: 6px слева/справа, 3px сверху/снизу.
*   **Панели инструментов (Toolbars):** 
    *   Высота одной строки панелей: **28px** (если панели занимают 2 строки — суммарно **56px**).
    *   Размер графических кнопок-иконок: **24x24px** (внутренняя иконка **16x16px** + 4px паддинг со всех сторон).
    *   Разделитель между блоками кнопок: вертикальная линия шириной **2px**.
*   **Высота панели вкладок документов (MDI Tabs):** **24px**. Шрифт вкладок — 8pt Tahoma.

### 3. Горизонтальная сетка (Слева направо при разрешении 1024x768)
*   **Левая панель Workspace (Дерево проекта / I/O View):** 
    *   Фиксированная ширина: **260px**.
    *   Внутренние отступы (Padding) элементов дерева: **4px** сверху/снизу, индент (отступ) каждого уровня вложенности — **16px**.
    *   Нижние вкладки переключения (`Project` / `I/O`): высота **22px**, ширина вкладки подстраивается под текст.
*   **Центральный разделитель (Сплиттер):** Ширина **4px** (интерактивная зона изменения размера окон).
*   **Центральное окно редактора кода (Code Space):** 
    *   Динамическая ширина: вся оставшаяся область (**~500px** при открытом окне Processor).
    *   Левое серое поле номеров строк и точек останова (Line Number Margin): ширина **34px** (отступ текста номеров строк от края — 4px).
*   **Правое окно диагностики (Processor / Registers):**
    *   Фиксированная ширина: **260px**.
    *   Ширина колонки `Name`: **140px**, ширина колонки `Value`: **120px**. Высота одной строки таблицы — **18px**.

### 4. Нижняя рабочая зона (Панель вывода логов)
*   **Высота окон вывода (Build, Message):** Фиксированная базовая высота **140px**.
*   **Нижние вкладки переключения в логах:** Высота **22px**.
*   **Внутренний отступ текста лога:** **5px** от левого края окна. Каждая новая строка сообщения имеет высоту **16px**.

### 5. Нижняя статус-строка (Status Bar)
*   **Общая высота:** **20px**.
*   **Разделение на секции:**
    *   Секция текстового статуса (`Ready`): динамическая, занимает **50%** ширины.
    *   Секция таргета (`ATmega8A` / `AVR Simulator`): фиксированная ширина **200px**.
    *   Секция координат курсора (`Ln 1, Col 1`): фиксированная ширина **120px**.
    *   Секции флагов клавиатуры (`CAP`, `NUM`): 4 секции по **40px** каждая.

### 6. Цветовая палитра интерфейса (HEX-коды)
*   **Фон окон кода и таблиц:** `#FFFFFF` (Чистый белый).
*   **Фон номеров строк, неактивных зон интерфейса и сплиттеров:** `#D4D0C8` (Windows Classic Grey).
*   **Цвет текста интерфейса (основной):** `#000000` (Черный).
*   **Подсветка синтаксиса в редакторе кода:**
    *   Команды процессора (`LDI`, `OUT`) и директивы препроцессора (`.cseg`, `.org`): `#0000FF` (Синий).
    *   Строки комментариев (все, что после `;`): `#008000` (Зеленый).
    *   Шестнадцатеричные и двоичные числа (`0xFF`, `0b001`): `#FF0000` (Красный) или черный в зависимости от версии плагина.
*   **Индикаторы отладки:**
    *   Точка останова (Breakpoint маркер): `#800000` (Бордовый круг диаметром **12px**).
    *   Стрелка текущей строки (Исполняемый шаг): `#FFFF00` (Желтый фон всей строки или желтая стрелка на сером поле).
*   **Интерактивные биты в I/O View (Квадраты):**
    *   Размер квадрата бита: **10x10px**, отступ между соседними битами — **3px**.
    *   Состояние `0` (сброшен): цвет контура `#808080` (серый), внутреннее поле `#FFFFFF` (белое).
    *   Состояние `1` (установлен): цвет контура `#000080` (темно-синий), внутреннее поле `#0000FF` (ярко-синий).
    *   Цвет текста бита, если состояние изменилось на текущем шаге: `#FF0000` (Красный).
