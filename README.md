# Архитектурное руководство: Современная CLI-экосистема для работы с AVR (Замена AVR Studio)

## 1. Концепция и Философия Системы
Данный документ описывает создание современной, легковесной и независимой от устаревшего ПО среды управления, компиляции и эмуляции для 8-битных процессоров AVR (на базе ATmega8A/ATmega16) внутри редакторов семейства VS Code / VScodium. 

Главная цель — полностью заменить GUI-функции устаревшей AVR Studio 4 универсальным интерфейсом командной строки (CLI) через оболочки **PowerShell (совместимость от версий 1.0 до 7.6.0+)**, изолировав кросс-компилятор и инструментарий программирования в единую управляемую структуру папок.

---

## 2. Логическая структура папок и Изоляция Процессоров
Для исключения проблем с путями Windows и разрядностью операционных систем, структура каталогов стандартизируется. Компиляторы под разные ядра (архитектуры) жестко изолируются:

```text
AI_model_mini_RG/
│
├── .vscode/                     # Конфигурация рабочей среды VScodium
│   ├── c_cpp_properties.json    # Настройка путей IntelliSense для C++
│   ├── tasks.json               # Автоматизация вызова сценариев PowerShell
│   └── launch.json              # Конфигурация отладчика (gdb-static)
│
├── core_processors/             # Будущая папка со всеми кросс-компиляторами
│   ├── avr8_atmel/              # Выделенная папка процессоров AVR (8-бит)
│   │   ├── bin/                 # avr-gcc, avr-g++, avr-objcopy, avr-gdb
│   │   ├── avr/include/         # Заголовочные файлы ввода-вывода (io.h, mega8.h)
│   │   └── lib/                 # Статические библиотеки libc
│   │
│   ├── arm_cortex/              # (Перспектива) Смежная папка для 32-битных ARM
│   └── riscv/                   # (Перспектива) Смежная папка для RISC-V процессоров
│
├── src/                         # Исходный код лабораторных работ (C++)
│   ├── lab1_registers.cpp
│   ├── lab2_button.cpp
│   └── lab3_math.cpp
│
├── build/                       # Инструменты автоматизации и вывода
│   ├── Makefile                 # Инструкция сборки для утилиты Make
│   ├── build.ps1                # Управляющий скрипт PowerShell для компиляции
│   └── flash.ps1                # Управляющий скрипт PowerShell для прошивки
│
└── README.md                    # Настоящая интерактивная документация
```

## 3. Интеграция с PowerShell (Версии 1.0 - 7.6.0+)
Вместо работы с графическими окнами AVR Studio (I/O View, Workspace, Memory) вся конфигурация, выбор процессора, частоты тактования (`F_CPU`) и вывод регистров переносятся в консоль PowerShell.

### 3.1. Интерактивный CLI-интерфейс конфигурации
Управляющий скрипт `build.ps1` при запуске через задачи VScodium сканирует папку `core_processors/` и выводит интерактивное меню в консоль PowerShell:

1. **Выбор архитектуры процессора** (8-bit AVR / 32-bit ARM).
2. **Выбор конкретного чипа** (поиск по файлам `io.h`, например: ATmega8, ATmega16, ATmega328P).
3. **Выбор частоты генератора** (ввод значения: 1MHz, 4MHz, 8MHz, 16MHz) для автоматической передачи макроса `F_CPU`.
4. **Выбор действия** (Очистить / Скомпилировать / Извлечь HEX / Прошить).

Консольный вывод генерирует строгий отчет о распределении памяти (Flash/SRAM), дублируя функции окна *Build* старой AVR Studio.

## 4. Эмуляция и Программное взаимодействие с Электронным Процессором
Для полноценной эмуляции без использования старого GUI применяются два альтернативных подхода:

### 4.1. Цифровая эмуляция ядра (Отладка на низком уровне)
*   **Связка `avr-gdb` + Симулятор:** Специальный отладочный процессор запускается в режиме бэкэнда. 
*   **Консольный вывод состояния:** Через команды PowerShell GDB осуществляет пошаговое выполнение кода. Вместо окна *Registers* в AVR Studio, пользователь отправляет команду в консоль и получает моментальный слепок состояния регистров общего назначения (РОН R0-R31), указателя стека (SP) и регистра состояния (SREG).

### 4.2. Схемотехническая интерактивная эмуляция
Для визуального анализа сигналов (светодиоды, кнопки, матрицы, графические экраны) сгенерированный компилятором файл `.elf` или `.hex` подключается к программной модели процессора в среде аналого-цифрового моделирования **Proteus VSM (ISIS)**. Это позволяет полностью эмулировать физические процессы ввода-вывода (включая дребезг контактов) на полной тактовой скорости процессора.

## 5. Пошаговая карта переноса Лабораторных Работ на C++

При переносе старых алгоритмов на современный ООП-код C++ (стандарт C++17) соблюдаются следующие правила эквивалентности:

### 5.1. Лабораторная работа №1: Прямая работа с портами и циклами
*   **Логика AVR Studio (Asm):** Использование `ldi` и `out` для конфигурации `DDRB` и `PORTB`, декремент регистра через `dec` и условный переход `breq`.
*   **Реализация в C++ CLI:** Создание статических абстрактных классов-контроллеров портов. Прямое побитовое присвоение значений регистрам ввода-вывода через разыменование указателей на зафиксированные адреса памяти данных SRAM.

### 5.2. Лабораторная работа №2: Обработка внешних прерываний и кнопок
*   **Логика AVR Studio (Asm):** Циклический опрос пина через команду `sbis`/`sbic` или обработка вектора прерывания `INT0`/`INT1`.
*   **Реализация в C++ CLI:** Написание макросов прерываний `ISR()`. Реализация программных задержек `_delay_ms()` для подавления физического дребезга контактов кнопки, эмулируя задержки аппаратных таймеров.

### 5.3. Лабораторная работа №3: Математические вычисления и Знаковая арифметика
*   **Логика AVR Studio (Asm):** Использование команд `add`, `sub`, `adc`, `sbc` с обязательным ручным контролем флагов переноса (`C`), знака (`S`) и переполнения (`V`) в регистре `SREG`.
*   **Реализация в C++ CLI:** Использование встроенных базовых типов данных (`uint8_t`, `int8_t`). Имитация регистрового файла через структуры данных. Компилятор `avr-gcc` автоматически оптимизирует код и транслирует математические выражения в наиболее эффективные ассемблерные инструкции с учетом знаковых флагов процессора.

## 7. Протокол технической коммуникации (Связь модулей)

Вся система работает как единый механизм за счет четкого разделения ролей между файлами конфигурации, консолью PowerShell и компилятором/эмулятором. 

### 7.1. Роль файла состояния `echo.ctos` (Центральный узел связи)
Файл `echo.ctos` выступает в роли оперативного моста (шина данных среды) между действиями пользователя в терминале и инструментами сборки. В нем в текстовом ключ-значение формате хранятся:
*   **Активный профиль:** Ссылка на конкретный файл микроконтроллера в папке `Procs` (например, `Procs/ATmega8A.proc`).
*   **Текущая тактовая частота (`F_CPU`):** Частота в герцах для синхронизации задержек и таймеров эмулятора.
*   **Статус сессии эмуляции:** Порт подключения отладчика, активные точки останова (Breakpoints) и список отслеживаемых переменных (Watchlist).

Когда пользователь вводит команду смены процессора в PowerShell, скрипт перезаписывает `echo.ctos`, а затем автоматически обновляет `Makefile` и `.vscode/c_cpp_properties.json`. Это гарантирует, что редактор кода, компилятор и эмулятор всегда работают с одним и тем же чипом.

## 8. Спецификация профилей в папке `Procs`

Чтобы эмулятор в консоли понимал, как устроен конкретный 8-битный процессор (без использования старых библиотек AVR Studio), каждый чип в папке `Procs` описывается по строгому стандарту.

### 8.1. Структура документа процессора
Описание любого микроконтроллера в папке `Procs` делится на 4 информационных блока:

1.  **Блок геометрии памяти (Memory Layout):**
    *   Границы программной памяти `FLASH` (начальный адрес `0x0000`, конечный адрес `FLASHEND`) [0.1.63, cite: 1].
    *   Границы регистрового файла `РОН` (всегда `0x0000` – `0x001F` для 32 рабочих регистров `R0–R31`) [0.1.37, cite: 1].
    *   Границы пространства регистров ввода-вывода `РВВ / I/O` (стандартный диапазон `0x0020` – `0x005F`, что соответствует адресам `0x00` – `0x3F` для команд `IN`/`OUT`) [0.1.64, cite: 1].
    *   Границы оперативной памяти `SRAM` (от `0x0060` до `RAMEND` — вершина стека `SP`) [0.1.64, cite: 1].

2.  **Словарь регистров периферии (Register Mapping):**
    *   Таблица перевода названий регистров в физические адреса памяти и описание каждого из 8 битов.
    *   *Пример логики в документации:* Регистр `PORTB` -> Адрес в I/O `0x18` (в ОЗУ `0x38`) -> Биты `[PB7, PB6, PB5, PB4, PB3, PB2, PB1, PB0]`.
    *   Это позволяет пользователю писать в консоли понятную команду `get PORTB`, а эмулятор сам знает, что нужно прочитать ячейку памяти `0x38`.

3.  **Аппаратные правила портов (GPIO Logic):**
    *   Правила связки трех регистров (`DDRx`, `PORTx`, `PINx`) [0.1.50, 0.1.134, cite: 1].
    *   Документированная логика для эмулятора: если бит в `DDRx = 0` (вход) и бит в `PORTx = 1` (включен подтягивающий резистор Pull-Up), то при отсутствии внешнего сигнала в регистре чтения `PINx` автоматически выставляется `1` (высокий уровень) [0.1.47, 0.1.134, cite: 1].

4.  **Карта тактирования и таймингов (Clock & Cycles):**
    *   Количество машинных тактов на каждую операцию (например: `LDI` — 1 такт, `RJMP` — 2 такта, `RET` — 4 такта) [0.1.72, 0.1.77, 0.1.78, cite: 1].
    *   Формула пересчета тактов в реальное время для консольного секундомера (`Stop Watch`): \(\text{Время (мкс)} = \frac{\text{Счетчик тактов} \times 1\,000\,000}{\text{F\_CPU}}\).

## 9. Архитектура виртуального эмулятора в консоли

Поскольку мы отказываемся от графических окон AVR Studio, вся визуализация процессов внутри электронного процессора переносится в текстовый интерфейс (TUI — Text User Interface) в терминале PowerShell.

### 9.1. Механика пошагового выполнения (Step-by-Step Engine)
Эмулятор работает в режиме клиент-сервер внутри одной консоли:
1.  **Фоновое ядро симуляции** загружает в виртуальную память файл `main.elf` и ставит процессор на паузу на векторе сброса (`PC = 0x0000`) [0.1.63, cite: 1].
2.  **Интерфейс PowerShell** отправляет ядру команду (например, «сделать 1 шаг»).
3.  Ядро выполняет ровно одну инструкцию процессора, пересчитывает регистры, сдвигает счетчик тактов и возвращает слепок памяти обратно в PowerShell.
4.  PowerShell сравнивает старый слепок памяти с новым и выводит на экран **только изменившиеся данные** (подсвечивая их цветом, как это делала AVR Studio красным шрифтом).

### 9.2. Эмуляция внешних физических воздействий (Симуляция кнопок и датчиков)
В реальном МК и в AVR Studio пользователь нажимал мышкой на квадратики битов в окне *I/O View* (менял 0 на 1 в регистре `PINx`), чтобы имитировать нажатие кнопки.
В консольной архитектуре это реализовано через **Виртуальную шину стимулов (Stimulus Bus)**:
*   **Ручной ввод:** Команда в консоли мгновенно притягивает нужную ножку виртуального порта к «земле» (`0`) или «питанию» (`1`).
*   **Сценарный ввод (Авто-тесты для лабораторных):** Возможность заранее прописать сценарий (например: *«на 100-й миллисекунде зажать кнопку на `PD0`, подержать 150 мс для проверки защиты от дребезга контактов, затем отпустить»*). Эмулятор сам прогонит этот тест и выдаст готовую таблицу результатов для отчета.

## 10. Стандарты совместимости PowerShell (Версии 1.1 — 7.6.0)

Чтобы среда одинаково стабильно открывалась на любом компьютере (включая старые ПК в университетских аудиториях с Windows 7/10 и новые системы с PowerShell 7.6.0), документация закрепляет жесткие правила для всех будущих скриптов управления:

1.  **Отказ от специфичных командлетов новых версий:** Используются только базовые конструкции языка PowerShell, существующие с версии 1.0/2.0, и стандартные вызовы `.NET Framework`.
2.  **Универсальное цветовое форматирование:** Вместо современных ANSI-escape последовательностей (которые не работают в старом `powershell.exe` версий 1.1–5.1) для отрисовки таблиц регистров и флагов `SREG` используется нативный буфер консоли (`Write-Host -ForegroundColor`).
3.  **Единая кодировка файлов:** Все конфигурационные файлы (`echo.ctos`, профили в `Procs`, `Makefile`) сохраняются в кодировке `UTF-8 without BOM` или `ASCII` для исключения сбоев при чтении путей компилятором `avr-gcc`.
4.  **Независимость от путей установки:** Среда поддерживает как глобальные пути к компилятору, так и портативный режим (если компилятор и эмулятор лежат прямо внутри папки проекта на флешке).

## 11. Спецификация экрана терминала (TUI — Text User Interface)

Чтобы полностью заменить графический интерфейс AVR Studio 4 [0.1.243, cite: 7] и не открывать десятки разных окон, вывод информации в консоль PowerShell организуется по принципу **Единой приборной панели (Dashboard)**. При каждом пошаговом действии (или по запросу) терминал отрисовывает структурированный текстовый кадр, разделенный на 5 логических зон.

### 11.1. Общий макет экрана (ASCII-схема приборной панели)

--------------------------------------------------------------------------------

    21:   regs.r17 = -25;

    23:   PORTB = regs.r21;

 РАБОЧИЕ РЕГИСТРЫ ОБЩЕГО НАЗНАЧЕНИЯ (РОН R0 - R31):

### 11.2. Правила цветовой индикации и разметки (Совместимость PS 1.1 – 7.6.0)
Поскольку старые версии PowerShell не поддерживают сложную графику, визуальные акценты расставляются стандартной палитрой из 16 цветов буфера консоли (`Write-Host -ForegroundColor`):

1. **Маркер изменений (Дельта-подсветка):** Если регистр, флаг в `SREG` или пин порта изменил свое значение после последнего выполненного шага, перед ним ставится символ звездочки `*`, а сама строка окрашивается в **ярко-красный цвет (`Red`)** — полный аналог поведения окон *Register* и *Memory* в AVR Studio.
2. **Указатель текущей команды:** Строка кода, которая будет выполнена в следующем машинном такте, помечается стрелкой `->` и выделяется **желтым цветом (`Yellow`)** (замена желтой стрелки отладчика).
3. **Состояние пинов и флагов:** Активные единичные биты (`1`) в регистре `SREG` и регистрах портов `PINx`/`PORTx` подсвечиваются **зеленым (`Green`)**, а нулевые биты (`0`) — **темно-серым (`DarkGray`)** для мгновенного визуального считывания состояния ножек МК.
4. **Форматы чисел:** Рабочие регистры `R16–R31` всегда выводятся одновременно в шестнадцатеричном (`HEX`) и десятичном со знаком/без знака (`DEC`) форматах, чтобы не приходилось переводить дополнительный код отрицательных чисел вручную (например, `0xE7` сразу видно как `-25`).

## 12. Полный справочник команд CLI (Синтаксис и управление)

Управление средой осуществляется через единый командный диспетчер. Все команды регистронезависимы и разделены на 5 функциональных групп. Для удобства предусмотрены как полные имена команд, так и короткие алиасы (сокращения в 1–3 буквы).

### 12.1. Группа 1: Конфигурация проекта и выбор процессора (Работа с `Procs`)

| Команда (Алиас) | Аргументы и параметры | Описание действия |
| :--- | :--- | :--- |
| **`proc list`** (`pl`) | *нет параметров* | Сканирует папку `Procs` и выводит таблицу всех доступных профилей микроконтроллеров с их характеристиками (объем Flash, SRAM, EEPROM) [cite: 1]. |
| **`proc select`** (`ps`) | `<имя_чипа> [частота_МГц]` | Устанавливает целевой процессор и тактовую частоту. Автоматически прописывает их в `echo.ctos`, `Makefile` и `c_cpp_properties.json`.<br>*Пример:* `proc select atmega8 8` (выбирает ATmega8A на 8 МГц). |
| **`proc info`** (`pi`) | `[имя_регистра]` | Выводит техническую справку из папки `Procs` по текущему чипу. Если указан регистр (например, `pi TCCR0` или `pi SREG`), выводит таблицу назначения каждого его бита (замена чтения PDF-даташита). |

### 12.2. Группа 2: Сборка, компиляция и проверка памяти (Замена меню Build)

| Команда (Алиас) | Аргументы и параметры | Описание действия |
| :--- | :--- | :--- |
| **`build`** (`b`) | `[-opt <O0\|O1\|O2\|Os>]` | Запускает кросс-компилятор `avr-g++`, собирает `main.elf` и `main.hex` [0.1.142, cite: 12]. Позволяет на лету задать уровень оптимизации (для лабораторных рекомендуется `-opt O0` — без оптимизации, чтобы компилятор не вырезал пустые циклы и переменные). |
| **`clean`** (`cl`) | *нет параметров* | Удаляет все временные и выходные файлы (`.elf`, `.hex`, `.o`, `.map`, `.lss`), очищая проект [cite: 12]. |
| **`size`** (`sz`) | *нет параметров* | Анализирует `main.elf` и выводит подробную шкалу заполнения памяти: сколько байт и процентов занято в памяти программ (`Program / Flash`) и памяти данных (`Data / SRAM`). |
| **`disasm`** (`da`) | `[имя_функции]` | Открывает дизассемблированный листинг программы. Показывает, в какие именно ассемблерные команды (`LDI`, `OUT`, `ADD`, `SUB`, `BRNE`) превратился ваш код на C++ [0.1.244, cite: 7]. |

### 12.3. Группа 3: Управление потоком выполнения в Эмуляторе (Замена меню Debug)

| Команда (Алиас) | Аналог в AVR Studio | Описание действия |
| :--- | :--- | :--- |
| **`emu start`** (`es`) | `Ctrl+Shift+Alt+F5` (*Start Debugging*) | Загружает `main.elf` в виртуальное ядро процессора, инициализирует память нулями, ставит указатель `PC` на начало функции `main()` и открывает интерактивную консоль эмулятора. |
| **`step`** (`s`) | `F11` (*Step Into*) | Выполняет ровно 1 шаг программы с заходом внутрь вызываемых функций и подпрограмм. После шага обновляет приборную панель TUI. |
| **`stepi`** (`si`) | *Step Instruction* | Выполняет ровно **одну ассемблерную машинную команду** (1–3 такта процессора) [cite: 1]. Идеально для пошагового разбора лабораторных по регистрам РОН и флагам `SREG`. |
| **`next`** (`n`) | `F10` (*Step Over*) | Выполняет текущую строку кода C++, но не заходит внутрь функций (позволяет за долю секунды прошагать функцию `_delay_ms(500)` целиком). |
| **`finish`** (`fin`) | `Shift+F11` (*Step Out*) | Мгновенно выполняет оставшийся код текущей подпрограммы или прерывания и останавливается на строке возврата в основную программу. |
| **`run`** (`r`) | `F5` (*Run*) | Запускает непрерывное выполнение программы до тех пор, пока процессор не встретит точку останова (Breakpoint) или пользователь не нажмет `Ctrl+C` (`Break`). |
| **`auto`** (`au`) | `Alt+F5` (*Auto Step*) | Режим «живой мультипликации»: эмулятор сам делает шаги с заданной паузой (например, 2 шага в секунду) и перерисовывает экран в реальном времени. Позволяет глазами наблюдать эффект «Бегущих огней» на битах регистра `PORTB`. |
| **`until`** (`u`) | `Ctrl+F10` (*Run To Cursor*) | `<номер_строки>` — запускает программу и останавливает её ровно на указанной строке исходного кода. |
| **`reset`** (`rst`) | `Shift+F5` (*Reset*) | Сбрасывает виртуальный микроконтроллер в исходное состояние после подачи питания (обнуляет регистры, возвращает `PC` в `0x0000`, сбрасывает счетчик тактов). |
| **`quit`** (`q`) | *Stop Debugging* | Завершает сессию эмуляции и возвращает консоль в обычный режим командной строки PowerShell. |

### 12.4. Группа 4: Точки останова и контроль времени (Breakpoints & StopWatch)

| Команда (Алиас) | Аргументы и параметры | Описание действия |
| :--- | :--- | :--- |
| **`bp add`** (`ba`) | `<строка \| функция \| адрес>` | Устанавливает точку останова (замена клавиши `F9`). Можно остановить процессор на конкретной строке (`ba 15`), при входе в функцию (`ba calc`) или при вызове прерывания таймера (`ba TIMER1_OVF_vect`). |
| **`bp list`** (`bl`) | *нет параметров* | Выводит список всех активных точек останова с их номерами. |
| **`bp del`** (`bd`) | `<номер_точки \| all>` | Удаляет конкретную точку останова или очищает все точки сразу (`bd all` — аналог *Remove Breakpoints*). |
| **`timer reset`** (`tr`) | *нет параметров* | Обнуляет счетчик машинных тактов (`Cycle Counter = 0`) и секундомер (`Stop Watch = 0.00 us`) на текущем шаге. Используется для точного замера времени выполнения отдельных кусков кода и прерываний. |

### 12.5. Группа 5: Чтение и принудительное изменение памяти, регистров и входов (Инспекция и Стимулы)

| Команда (Алиас) | Аргументы и параметры | Описание действия |
| :--- | :--- | :--- |
| **`reg`** (`rg`) | `[R0..R31 \| SREG \| all]` | Выводит состояние рабочих регистров. Если вызвать с параметром присвоения (`reg R16 = 0x55` или `reg R17 = -25`), принудительно записывает новое число в регистр на паузе. |
| **`port`** (`pt`) | `<A\|B\|C\|D>` | Выводит детальную расшифровку выбранного порта: направление каждой ножки (`IN`/`OUT`), состояние подтяжки (`Pull-Up` / `Hi-Z`) и логический уровень на выходе (`HIGH` / `LOW`) [0.1.50, 0.1.134, cite: 1]. |
| pin (pn) | <имя_пина> <0\|1\|toggle> | Имитация внешнего физического воздействия (нажатие кнопки / сигнал датчика).
Пример: pin PD0 0 — подает низкий уровень (замыкает кнопку на землю) на вход PD0 (записывает 0 в бит 0 регистра PIND).
Пример: pin PA 155 — подает сразу 8-битное число 155 на весь входной порт PINA (для проверки регуляторов из ЛР). |
| watch (w) | <имя_переменной> | Добавляет переменную из кода C/C++ в нижний блок постоянного наблюдения на приборной панели (аналог окна Watch). |
| mem (m) | <sram\|flash\|eeprom> <адрес> [длина] | Выводит шестнадцатеричный дамп выбранной области памяти (замена окна Memory). Позволяет также изменить любую ячейку памяти вручную: mem sram 0x0060 = 0xFF. |

### 13.1 Внутреннее устройство файла echo.ctos
Файл echo.ctos, который уже лежит в корне проекта, будет хранить текущее состояние среды, выбранный процессор и настройки сессии эмуляции.

**Содержимое echo.ctos:**

```
# Системный файл состояния AVR CLI Studio
[ActiveSession]
ProcessorProfile = ATmega8A
MCU_Target = atmega8
Define_Tag = __AVR_ATmega8__
F_CPU = 8000000UL
Optimization = O0

[Paths]
; Портативный вариант: можно просто кинуть bin тулчейна в <проект>\tools\bin -
; avr.ps1 найдёт его ПЕРВЫМ (до этой записи и до классического пути), без правки конфигов.
ToolchainBin = C:/Program Files (x86)/Atmel/AVR Tools/AVR Toolchain/bin
ToolchainInc = C:/Program Files (x86)/Atmel/AVR Tools/AVR Toolchain/avr/include
ProcsDir = ./Procs

[EmulatorState]
LastPC = 0x0000
CycleCounter = 0
StopWatch_us = 0.00
ActiveBreakpoints = main
WatchVariables = 

```
